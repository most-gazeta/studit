# js://master на хостинге PHP + MySQL (cPanel)

Сайт = статическая сборка фронтенда + папка `api` с PHP-бэкендом.
Никакого Node.js и Composer на хостинге не нужно — только PHP 7.4+ и MySQL.

```
public_html/
├── index.html          ← содержимое dist/ (после сборки)
├── assets/…            ← содержимое dist/assets/
└── api/                ← содержимое этой папки (server-php/)
    ├── .htaccess
    ├── config.php      ← ваша БД + секреты
    ├── index.php       ← весь API
    └── schema.sql      ← (можно не загружать)
```

## Шаг 1. База данных

1. cPanel → **phpMyAdmin** → слева выберите базу **mostnews_studit**.
2. Вкладка **SQL** → вставьте содержимое `schema.sql` → «Вперёд».
   Создадутся 3 таблицы: `users`, `progress`, `xp_events`.

## Шаг 2. Загрузите PHP-API

1. cPanel → **Файловый менеджер** → откройте `public_html`.
2. Создайте папку `api` и загрузите в неё `config.php`, `index.php`, `.htaccess`.
3. **Отредактируйте `config.php`**: смените `JWT_SECRET` на случайную строку
   и — важно — **обновите пароль БД**, т.к. старый «засветился» в переписке
   (смените его в cPanel → «Базы данных MySQL»).

## Шаг 3. Создайте таблицы и демо-аккаунты

Откройте в браузере (однократно):

```
https://ВАШ-ДОМЕН/api/seed?key=jsmaster-setup-2026
```

Должен вернуться JSON `{"ok":true,...}`. Появятся аккаунты:
- админ: `admin@jsmaster.ru` / `admin123`
- студенты: `maria@demo.ru`, `ilya@demo.ru`, `anya@demo.ru` / `demo123`

После этого смените `SETUP_KEY` в `config.php` (или удалите маршрут `/seed`).

Проверка БД: `https://ВАШ-ДОМЕН/api/health` → `{"ok":true,"db":"connected"}`.

## Шаг 4. Соберите фронтенд под ваш домен и загрузите

В корне проекта включите режим API и соберите:

```bash
cp .env.production.example .env.production   # внутри уже VITE_API_URL=/api
npm run build
```

Затем загрузите **содержимое** папки `dist/` (index.html + assets/) в `public_html/`.

> `VITE_API_URL=/api` — относительный путь, поэтому работает на любом домене
> без правок: запросы идут на `https://ВАШ-ДОМЕН/api/…`.
>
> Без этого шага сайт работает в демо-режиме (аккаунты хранятся в браузере
> посетителя, а не в MySQL) — тоже полностью функционален, но без общей базы.

## Шаг 5. Проверка

1. Откройте сайт → «Войти» → `admin@jsmaster.ru` / `admin123`.
2. Личный кабинет → «Админ-панель»: пользователи подтягиваются из MySQL.
3. Пройдите квиз/задачу → прогресс сохранится в БД (авто-синхронизация ~1 c).

## Безопасность (чек-лист)

- [ ] Сменён пароль БД (старый был в чате) и обновлён в `config.php`
- [ ] `JWT_SECRET` — длинная случайная строка
- [ ] `SETUP_KEY` сменён после `/seed`
- [ ] Сайт открыт по **HTTPS** (cPanel → AutoSSL)
- `config.php` закрыт от прямого доступа через `.htaccess`

## Если что-то не так

| Симптом | Причина / решение |
|---|---|
| `404` на `/api/…` | не работает mod_rewrite: в cPanel проверьте, что `.htaccess` читается (Apache), либо перенесите правило в `httpd.conf` |
| «Не удалось подключиться к базе» | неверные данные в `config.php`; на cPanel хост почти всегда `localhost` |
| фронтенд пишет «Сервер недоступен» | `VITE_API_URL` не попал в сборку — пересоберите с переменной |
